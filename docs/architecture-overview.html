📂 Backup Manager — 项目架构全景

基于 Git 反向追踪模式的文件聚合备份可视化管理工具 · 2026-07-16

项目定位

让用户以"指定要备份什么"（白名单）而非"排除什么"（黑名单）的直观方式管理备份。通过软链接将分散在文件系统中各处的源文件聚合到一个 Git 仓库内，实现统一版本管理 + 按需备份。

核心设计原则：反向追踪模式（Reverse Tracking）——用户主动指定哪些文件需要备份，未指定的自动忽略；软链接聚合管理源文件；前后端一体单进程运行。

核心价值

  • 反向追踪：白名单模式，指定备份而非排除
  • 软链接聚合：源文件分散存放，统一管理
  • Git 版本控制：增量检测 + 自动提交 + 可选推送
  • 可视化界面：React SPA，拖拽式选择文件
  • 加密安全：AES-256-GCM 保护 Git 认证凭据

备份执行核心流程

增量检测算法：mtime + fileSize 双字段比较。当源文件的修改时间或大小与数据库中记录不一致时，即判定为变更并同步到 data/。目录级 symlink 使用递归遍历 + 循环检测，确保安全。

镜像一致性保障

CREATE Symlink:
  1. SafeResolve 验证源路径
  2. os.Symlink(sourcePath → .links/relativePath)
  3. CopyFile/CopyDir(sourcePath → data/relativePath)  ← 同步复制
  4. INSERT INTO symlinks

DELETE Symlink:
  1. os.Remove(.links/relativePath)
  2. os.Remove(data/relativePath)
  3. 清理空目录
  4. DELETE FROM symlinks

UPDATE Symlink Target:
  1. 删除旧 .links/ + data/ 文件
  2. 创建新软链接 + 复制新源文件
  3. UPDATE symlinks SET target_path, file_size, modified_at
关键决策：备份执行阶段不再重新扫描全部源文件，仅做增量同步。这得益于添加/删除/修改软链接时已经同步维护了 data/ 目录的镜像状态。

数据库 Schema

CREATE TABLE repos (
    id            TEXT PRIMARY KEY,
    name          TEXT NOT NULL,
    path          TEXT NOT NULL UNIQUE,
    created_at    DATETIME DEFAULT (datetime('now')),
    updated_at    DATETIME DEFAULT (datetime('now')),
    last_backup_at DATETIME,
    status        TEXT DEFAULT 'active'   -- active | error | backing_up
);

CREATE TABLE repo_configs (
    repo_id             TEXT PRIMARY KEY,
    remote_url          TEXT,
    branch              TEXT DEFAULT 'main',
    auto_backup         INTEGER DEFAULT 0,
    auto_backup_interval TEXT,             -- cron expression
    git_user_name       TEXT,
    git_user_email      TEXT,
    FOREIGN KEY (repo_id) REFERENCES repos(id) ON DELETE CASCADE
);

CREATE TABLE repo_auths (
    repo_id              TEXT PRIMARY KEY,
    auth_type            TEXT NOT NULL DEFAULT 'none',  -- none | ssh_key | password
    ssh_private_key      BLOB,           -- AES-GCM encrypted
    ssh_private_key_path TEXT,
    username             TEXT,
    password_encrypted   BLOB,           -- AES-GCM encrypted
    updated_at           DATETIME,
    FOREIGN KEY (repo_id) REFERENCES repos(id) ON DELETE CASCADE
);

CREATE TABLE symlinks (
    id              TEXT PRIMARY KEY,
    repo_id         TEXT NOT NULL,
    relative_path   TEXT NOT NULL,       -- path under .links/
    target_path     TEXT NOT NULL,       -- absolute source file path
    type            TEXT NOT NULL,       -- file | directory
    file_size       INTEGER,
    modified_at     DATETIME,
    created_at      DATETIME DEFAULT (datetime('now')),
    FOREIGN KEY (repo_id) REFERENCES repos(id) ON DELETE CASCADE,
    UNIQUE(repo_id, relative_path)
);
